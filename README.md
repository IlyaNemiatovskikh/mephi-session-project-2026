# Сессионный проект по курсу «Безопасность GNU/Linux» - Настройка базовых средств защиты ОС GNU/Linux

Вместо номера зачетной книжки использван бухгалтерский шифр: **374537**.

Проект выполнен на **РЕД ОС 8.0.3 Standard Server Minimal** без графической среды, в виртуальной машине **RedOS8** в Oracle VirtualBox. 

## Раздел 1. Установка дистрибутива

### 1.1. Настройка сети

Сетевой интерфейс получает IPv4-адрес по DHCP. На [скриншоте сети](screenshots/01-network.png) видны динамический адрес и маршрут с `proto dhcp`.

### 1.2. Настройка имени хоста

Задано имя `mephi-2026.domain.local`. Вывод `hostnamectl --static` сохранён на [скриншоте сети](screenshots/01-network.png), это же имя указано в [журнале nginx](journalctl.out).

### 1.3. Проверка сетевой связности

Команда `ping -c 4 8.8.8.8` получила четыре ответа, потерь пакетов нет. Результат: [ping.out](ping.out).

## Раздел 2. Управление программным обеспечением

### 2.1. Обновление дистрибутива

Пакеты обновлены через `dnf`. В [истории транзакций](dnf.out) записана команда `dnf -y --refresh upgrade`; [скриншот обновления](screenshots/02-update.png) показывает успешное завершение транзакции. После обновления выполнен `semodule -B`, затем проверен режим SELinux Enforcing. Команды сохранены в [history.out](history.out).

### 2.2. Установка пакетов из репозиториев

Пакеты `nginx` и `libcap-ng-utils` установлены через `dnf`. Установка и проверка `rpm -q` показаны на [скриншоте пакетов](screenshots/02-packages.png), транзакция есть в [dnf.out](dnf.out).

### 2.3. Установка локального RPM-пакета

Бинарный пакет `tcpdump.x86_64` загружен в `/tmp` командой `dnf download --resolve --destdir=/tmp tcpdump.x86_64` и установлен через `rpm -ivh /tmp/tcpdump*.rpm`.

Загрузка, установка и версия пакета видны на [скриншоте пакетов](screenshots/02-packages.png). Команды записаны в [history.out](history.out). Установка через `rpm` не входит в историю транзакций `dnf`.

## Раздел 3. Управление файловыми системами

### 3.1. Создание файловой системы

На втором диске `/dev/sdb` размером 2 ГиБ создан один раздел `/dev/sdb1`, занимающий доступное пространство диска. Раздел отформатирован в ext4 с меткой `MEPHI_WEB`. Разметка и результат `lsblk` видны на [скриншоте файловой системы](screenshots/03-filesystem.png).

### 3.2. Монтирование файловой системы

Создана точка `/mephi-web`. Раздел смонтирован вручную командой `mount /mephi-web`. Для автоматического монтирования в [fstab](fstab) добавлена строка:

```fstab
LABEL=MEPHI_WEB /mephi-web ext4 defaults 0 2
```

Ручное монтирование показано на [скриншоте файловой системы](screenshots/03-filesystem.png). После перезагрузки раздел остался смонтирован в `/mephi-web`, что видно на [итоговом скриншоте](mephi-screenshot.png).

## Раздел 4. Управление сервисами

### 4.1. Управление веб-сервером

Служба nginx запущена командой `systemctl start nginx` и включена в автозагрузку через `systemctl enable nginx`. На [скриншоте службы](screenshots/04-nginx.png) видны состояния `active (running)` и `enabled`. После перезагрузки состояния `active` и `enabled` подтверждены на [итоговом скриншоте](mephi-screenshot.png).

### 4.2. Журналирование

Сообщения nginx для текущей загрузки сохранены командой `journalctl -u nginx -b --no-pager` в [journalctl.out](journalctl.out). Файл собран после контрольной перезагрузки и содержит успешную проверку конфигурации и запуск службы.

## Раздел 5. Управление доступом

### 5.1. Дискреционное управление доступом (DAC)

Созданы пользователи и группы:

| Пользователь | UID | Основная группа | GID |
|---|---|---|---|
| `user1` | 5501 | `developers` | 1000 |
| `user2` | 5502 | `developers` | 1000 |
| `user3` | 5503 | `developers` | 1000 |
| `curator1` | 5504 | `curators` | 4444 |
| `curator2` | 5505 | `curators` | 4444 |

Учётные записи подтверждены файлами [passwd](passwd), [group](group) и [скриншотом настройки доступа](screenshots/05-acl.png).

Каталог `/data/mephi-2026` принадлежит `root:developers`, имеет режим `2770` и бит SGID. ACL дают разработчикам чтение и запись, кураторам чтение файлов и проход по каталогам. Остальным пользователям доступ закрыт. Default ACL задают наследуемые права для новых файлов и каталогов. Права каталога сохранены в [stat.out](stat.out), ACL каталога и тестовых файлов в [acl.out](acl.out).

На [скриншоте проверок доступа](screenshots/06-acl-tests.png) показаны создание файлов каждым разработчиком, запись в файлы друг друга и чтение всех трёх файлов обоими кураторами. Во вложенном каталоге проверены наследование прав, совместная запись и чтение куратором. Попытки кураторов изменить, создать и удалить файлы завершились отказом, чтение от имени `nobody` также запрещено.

Проверки подтверждают доступ к созданным тестовым файлам. Default ACL не гарантируют одинаковые права при любом способе создания файла: запрошенный программой режим или последующий `chmod` могут ограничить доступ.

### 5.2. Привилегии (уменьшение количества set-UID-программ)

У `/usr/sbin/tcpdump` снят бит SUID и назначены capabilities `cap_net_raw,cap_net_admin=ep`. Набор привилегий сохранён в [getcap.out](getcap.out).

Пользователь `user1` запустил `tcpdump` на интерфейсе `lo` и захватил два ICMP-пакета. На [скриншоте проверки tcpdump](screenshots/07-capabilities.png) видны права исполняемого файла без SUID и результат захвата. Сохранение capabilities после перезагрузки показано на [итоговом скриншоте](mephi-screenshot.png).

### 5.3. Мандатное управление доступом (MAC)

SELinux работает в режиме Enforcing: [getenforce.out](getenforce.out). В [selinux-config](selinux-config), копии `/etc/selinux/config`, задано `SELINUX=enforcing`.

В [nginx.conf](nginx.conf) корнем сайта указан `/mephi-web`. Для пути `/mephi-web(/.*)?` добавлено постоянное правило `semanage fcontext` с типом `httpd_sys_content_t`; контексты применены через `restorecon`. Правило, контекст каталога и проверка `nginx -t` видны на [скриншоте SELinux](screenshots/08-selinux.png).

Контекст каталога сохранён в [stat.out](stat.out). Режим Enforcing, контексты каталога и страницы, а также ответ nginx после перезагрузки показаны на [итоговом скриншоте](mephi-screenshot.png).

## Раздел 6. Аутентификация

### 6.1. Ограничение входа для пользователей

В PAM-службе [login](login) подключён `pam_access.so` с отдельным файлом [mephi-console-access.conf](mephi-console-access.conf). Правила запрещают группе `curators` консольный вход и разрешают остальным пользователям проход этой проверки.

На [скриншоте настройки PAM](screenshots/09-console-policy.png) показано добавление правил. Значение `PASS_MAX_DAYS 99999` на этом снимке относится к состоянию до настройки паролей в пункте 6.2.

Проверены отказы при входе `curator1` и `curator2`, а также успешный вход `user1` на tty2. Результаты сохранены в [login-tests.out](login-tests.out) и на [скриншоте проверок входа](screenshots/12-console-tests.png).

### 6.2. Управление паролями

Модуль `pam_pwquality` подключён в стандартном PAM-стеке, что видно на [скриншоте настройки PAM](screenshots/09-console-policy.png). В [pwquality.conf](pwquality.conf) заданы `minlen = 12`, нулевые `dcredit`, `ucredit`, `lcredit`, `ocredit`, а также `enforcing = 1` и `enforce_for_root`. Проверка качества обязательна и при назначении пароля от root. Активного переопределения `dictcheck` в итоговом файле нет.

Для новых учётных записей в [login.defs](login.defs) задано `PASS_MAX_DAYS 90`. Для `root`, `user1`, `user2`, `user3`, `curator1` и `curator2` выполнено `chage -M 90`; срок подтверждён полями [shadow](shadow) и [скриншотом политики паролей](screenshots/10-password-policy.png).

На [скриншоте смены паролей](screenshots/11-passwords.png) показано успешное обновление паролей всех шести учётных записей.
